# 家庭资源多域数字孪生设计

## 目标

把当前以食品、临期和菜谱为中心的家庭资源产品，升级为覆盖食品、药品、健身器材和工具的确定性多域数字孪生。新增“身体档案 → 训练方案”链路，同时保持 AI 只能提议、代码负责校验、用户负责确认的安全边界。

## 用户问题

家庭中的药品、健身器材和工具已经能通过自由建库或拍照入库，但系统没有资源域语义：

- 药品没有剩余次数、每日用量和断药风险；
- 健身器材没有身体数据、训练目标和可用器材匹配；
- 工具没有维护、保修和耗材语义，仍可能被食品日耗模型误判；
- GraphRAG、AI 意图和数字孪生说明偏食品，展示与真实业务能力不一致。

## 资源域

统一使用六个字符串资源域：

| 标识 | 名称 | 主要内容 |
|---|---|---|
| `food` | 食品 | 食材、饮料、调味品 |
| `medicine` | 药品 | 常备药、急救用品、每日用药 |
| `fitness` | 健身器材 | 哑铃、弹力带、瑜伽垫、跑步机 |
| `tool` | 工具 | 五金、维修、清洁工具及耗材 |
| `daily` | 日用品 | 洗护、纸品、衣物等 |
| `other` | 其他 | 未识别资源 |

资源域由名称、库名和识别类别共同推断。旧数据没有域字段时，在加载、同步和孪生计算中按同一函数补全，不要求用户重建数据。

## 数据模型

`Item` 增加：

- `domain: string`
- `dosePerDay: number`：用户明确填写的每日药品数量，不可由模型猜测
- `maintenanceDays: number`：距离维护或保修到期的天数，0 表示未设置

`Library` 增加 `domain: string`。

`Profile` 增加：

- `heightCm: number`
- `weightKg: number`
- `age: number`
- `trainingGoal: string`：`fat_loss | muscle | endurance | mobility | general`
- `trainingLevel: string`：`beginner | intermediate | advanced`
- `weeklyDays: number`
- `limitations: string`
- `trainingEnabled: boolean`

身体档案仅本机保存，进入自由流转快照时必须遵循用户显式接续行为，不进入普通 GraphRAG 提示。

## 数字孪生

食品继续使用人数、餐次、保质期和数量推演耗尽与浪费。

药品使用用户填写的每日用量推演剩余天数。人数和餐次不得影响药品。药品风险文案为“预计第 N 天药量不足”；系统不生成剂量建议，只复述用户输入的用量。

工具和健身器材默认不产生日耗。工具在设置了维护天数时产生维护风险；健身器材数量为 0 时产生不可用风险。只有具有明确日耗的耗材才进行耗尽推演。

## 训练方案

新增纯函数训练计划引擎，输入身体档案和当前可用健身器材，输出：

- BMI 与边界提示；
- 每周训练日；
- 动作、组数、次数或时长、休息时间、所需器材；
- 器材缺口与身体限制提示。

生成规则完全确定，不调用模型。BMI 极端、年龄较大或存在限制时只降低强度并提示咨询专业人士，不做诊断。

## UI

数字孪生增加资源域切换：全部、食品、药品、健身、工具。情景按钮只显示当前域适用的情景。

新增身体档案浮层，包含输入、BMI、训练计划和器材匹配。训练计划不直接写库存，器材数量变化后重新计算。

## AI 与图谱

新增药品、训练和工具意图。AI 可以解释孪生结果和训练计划，但写操作仍走白名单、预览、确认、幂等守卫。

图谱物品节点增加资源域属性；同一物品可以连接域类别、药品方案、训练动作或工具维护概念。

## 验收

- 非食品资源域不再受餐次因子影响；
- 药品按每日用量计算断药日；
- 工具不会因数量少而被自动当成食品缺货；
- 同身体档案与器材输入每次生成相同训练计划；
- 训练计划只使用已入库器材或自重动作；
- 旧数据可自动补全资源域；
- 同步与本地恢复保留新增字段；
- Hypium、Node、GuardrailBench、静态检查和 HAP 构建通过；
- 模拟器完成药品、健身、工具和身体档案的真实交互截图。

## 非目标

- 不提供诊断、处方或康复治疗建议；
- 不声称训练计划替代医生或专业教练；
- 不把 AI 生成的训练组数直接写入库存；
- 不在本轮引入 2in1 真机发布或应用市场签名。
