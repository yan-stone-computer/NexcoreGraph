# 启核图策 NexcoreGraph · 演示录屏脚本（3~5 分钟）

> 目标：一条视频讲清"AI 是主体、数据是真数据、多端能接力"三件事。
> 拍摄前先按第 0 节做准备——这几步没做，录到一半会卡壳。

## 0. 开录前的准备（约 5 分钟）

1. **起后端**（电脑上一条命令，会把手机该填的地址打出来）：
   `powershell -ExecutionPolicy Bypass -File tools/start-lan.ps1`
2. **确认设备对应关系**（重要：模拟器重启后端口会对调，端口号不能靠记）：
   `hdc list targets`，再对每个设备跑 `uitest dumpLayout`，看根节点边界——
   宽 1320×2848 是手机，2880×1920 是平板。**按分辨率认设备，不要按端口号认。**
3. **登录**：手机、平板都用同一账号（手机号或邮箱 + 验证码；若用邮箱，验证码会真实发到收件箱）。
4. **关掉 AI 助手浮层**：它是半模态，开着会盖住屏幕下半部分，底部标签点不动。录之前先关。
5. **清一遍库存**：留 2~3 件带保质期的物品即可（例如鸡蛋、牛奶、番茄），临期效果才明显。
6. 准备一张**冰箱或货架的照片**放在相册里（现场拍也行；模拟器无相机时用相册）。

## 2. 录制要点

- **每条只做一件事**，动作完成后再切下一个镜头，避免连续操作让观众跟不上。
- **识别过程不要剪掉**：等 2~3 秒的过程本身就是"真 AI"的证据，反而要保留并配字幕（"通常 1~3 秒"）。
- **数字要对得上**：旁白报的数字必须与画面一致（临期件数、识别件数、同步耗时）。
- 若某次识别返回 0 项（拍到了不相干的图），**不要重录糊过去**，正好可以讲"它不会硬凑物品"——这是加分点。
- 手机截图/录屏分辨率建议 1080p；平板用横屏录。

## 3. 现场演示的备用话术（被问到时的回答）

| 可能的问题 | 回答 |
|---|---|
| AI 是不是只是调了个接口？ | 讲三件事：GraphRAG 证据装配（回答带路径与来源）、工具协议（写操作先确认）、意图路由（四类问题 0 次模型调用）。 |
| 数据放哪、隐私怎么保证？ | 局域网自建：后端在用户电脑上，端侧不持有任何模型密钥，聊天正文与图片二进制不随流转同步。 |
| 为什么有些能力没做？ | 直说：本项目是**元服务**形态，环境光传感器在元服务下编译期就被拦（可出示报错），端侧数据库与端侧 OCR 也无元服务标记；要放开需改 App 形态或申请权限。 |
| 和记账 App 的区别？ | 记账是"人填表、AI 聊天"；这里是"AI 出结构、人只补缺"，且库存直接驱动方案、采购与协作。 |
| 多端怎么做的？ | 同一份快照 DTO + 版本号过滤 + 按 id 原地合并；2 秒轮询，实测 7 秒内对方自动呈现。 |

## 4. 已经踩过的坑（录之前看一眼，省得重录）

1. **底部标签点不动**：多半是 AI 助手半模态还开着盖住了下半屏——先关浮层再操作。
2. **端口对调**：模拟器重启后 5555/5557 可能互换；按分辨率认设备（见第 0 节第 2 步）。
3. **相册选图后没反应**：确认后端在跑（`/api/health` 能返回 JSON），端侧读图超过 12 秒会主动报错而不是一直转圈。
4. **识别特别慢**：上游排队时网关会自动换模型；如果持续慢，检查是否有人在用同一把 Key 跑别的任务。
