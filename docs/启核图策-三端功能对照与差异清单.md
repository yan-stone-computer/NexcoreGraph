## 二、两端相对鸿蒙端的缺口（按建议修复顺序）

### P0 · 视觉与登录（一眼能看出不一样）

| 项 | 现状 | 要做 |
|---|---|---|
| 主题令牌 | 小程序仍香槟金；Web 本轮已完成 | 小程序 `styles/theme.scss` / `variables.scss` 换成与 `Tokens.ets` 同值，默认浅色；组件里写死的色值（`StatCard color="#A5803C"` 等）改为引用令牌 |
| 色板切换 | 两端都没有"启核 / 经典"两套 | 与 Web 对齐：`nexcore`（默认）/ `classic` 两套 × 明暗两态 |
| 登录页 | 两端是固定验证码 `123456` | 接后端真实验证码（`/api/auth/code` + `/api/auth/login`），60 秒倒计时，页面上标注"已连接 http://…（局域网自建服务器）"；Web/平板按鸿蒙的左右分栏 |
| 导航信息架构 | 鸿蒙＝首页 / 资源库 / 工作台 / 我的 + 悬浮 AI 球；Web＝AI 工作台 / 首页看板 / 资源库 / 资源图谱 / 协作工作台 | 统一为鸿蒙四 Tab 结构，图谱与 AI 工作台作为入口或浮层，不再各占一个主导航位 |

### P1 · 能力缺口（鸿蒙有、两端没有）

1. **自然语言指令层 + 指令手册**（`Commands.ets`，5 组指令：看一眼库存 / 建库与改名 / 物品增减与移动 / 采购与方案 / 多端与设置）——两端都缺，是"所有操作一句话完成"的核心卖点。
2. **活同步**（改完自动发、对端 2 秒内自动收）——两端只有手动"上传 / 拉取 + 模拟他端"。
3. **跨设备自由流转**（续接 + 流转中转 + 桌面流转面板）——鸿蒙 + 后端 `flow-bridge.js` 已有，两端缺。
4. **TTS 播报**——鸿蒙有，Web 只有语音输入（Web Speech），小程序语音输入与播报都没有。
5. **数据分析看板（AnalyticsBoard）**——鸿蒙有独立看板（KPI + 库存构成 + 趋势 + 当日小结），两端只有首页上的 KPI 卡。
6. **CSV 导入导出**（Web 有，小程序缺）；**打印采购清单**（Web 有，小程序缺）。
7. **响应式断点**：Web 有 1200 / 720 两档，小程序无；鸿蒙有三档 + 手表。

### P2 · 平台侧未落地（规范要求，尚未实现）

- 小程序：**订阅消息**（规范 M7 三个模板）、**隐私授权**（`onNeedPrivacyAuthorization`）、**真实 `msgSecCheck`**（当前是本地敏感词表）、**`chooseMedia`** 替换已弃用的 `chooseImage`。
- 小程序：`design-tokens.json` 还是 "Dark Champagne"，需与 `Tokens.ets` 一起更新为唯一来源，否则三端还会继续漂。

## 四、结论

两端的功能底座（拍照入库、库存管理、AI 编排、GraphRAG、协作工作台、多端同步）**已经齐了**，
与鸿蒙端的差距集中在三类：

1. **视觉**：小程序令牌与组件里的硬编码色值；
2. **交互模型**：登录方式、导航结构、指令层（"一句话完成"）、活同步与流转；
3. **平台能力**：TTS、断点、CSV / 打印、以及小程序的合规与订阅消息。

建议执行顺序：**小程序令牌与登录 → 指令层（两端）→ 活同步 + 流转 → TTS / 看板 / CSV / 打印 → 小程序合规**。
