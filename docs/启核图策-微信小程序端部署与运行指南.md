# 启核图策 NexcoreGraph 微信小程序端部署与运行指南

> 版本：v1.0  
> 日期：2026-11-11  
> 适用对象：参赛团队、部署人员、答辩演示人员和后续维护者  
> 小程序 AppID：`wx25e3afb6ce695963`

## 1. 本指南解决什么问题

本指南覆盖三种运行方式：

| 模式 | 用途 | 后端地址 | 微信域名校验 |
|---|---|---|---|
| 本机开发 | 微信开发者工具内调试完整功能 | `http://127.0.0.1:3000` | 关闭 |
| 局域网演示 | 手机、平板与后端电脑处于同一 WiFi | `http://电脑局域网IP:3000` | 开发/体验调试时关闭 |
| 公网正式部署 | 体验版和正式版长期使用 | `https://api.你的域名` | 微信后台白名单 + HTTPS |

生产环境不能依赖 `127.0.0.1`，也不能把 MySQL 3307、Node 3000 端口直接暴露给公网。正式版只暴露 Nginx 的 80/443，由 Nginx 反向代理到本机 Node 服务。

## 2. 系统组成

```text
微信小程序
  ├─ Taro/React 页面
  ├─ 本地库存与 GraphRAG
  └─ 请求 /api/*
        │
        ▼
Node.js 后端（默认 3000）
  ├─ 登录、家庭、同步、AI 网关
  ├─ GraphRAG 与知识库接口
  ├─ 审计链 /api/events/*
  └─ MySQL（默认 3307，开发环境）

可选：flow-bridge（默认 3100）
  └─ 跨设备快照流转
```

关键边界：

- 小程序负责界面、本地事实计算、GraphRAG 证据装配、预览确认和降级。
- Node 后端负责鉴权、MySQL 持久化、模型调用、审计链和外部服务代理。
- MySQL 保存账号、家庭成员、同步快照、AI 用量、图谱和追加式审计事件。
- AI Key 只允许存在服务端环境变量；正式包不携带真实 Key。

## 5. 本机最短启动路径

### 5.1 启动 MySQL

确认 3307 端口在监听：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -eq 3307 }
```

创建数据库：

```powershell
mysql -h 127.0.0.1 -P 3307 -u root -p `
  -e "CREATE DATABASE IF NOT EXISTS tianshu DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

数据库本身需要手工创建；`users`、`families`、`sync_snapshots`、`graph_nodes`、`event_journal` 等表会在后端启动时自动创建。

### 5.2 配置后端

```powershell
cd harmonyosapp/NexcoreGraph_harmonyos/backend
Copy-Item .env.example .env
```

本地最小配置：

```text
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3307
DB_USER=root
DB_PASSWORD=123456
DB_NAME=tianshu

AGNES_BASE_URL=https://api.agnes-ai.cn/v1
AGNES_API_KEY=填写服务端 Key
AGNES_MODEL=agnes-3.0-flash
AGNES_MODEL_ALT=agnes-2.5-flash
AGNES_VISION_MODELS=agnes-2.5-flash,agnes-3.0-flash

MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_USER=你的发件邮箱
MAIL_PASS=邮箱 SMTP 授权码

AUTH_SHOW_CODE=1
```

注意：

- `AUTH_SHOW_CODE=1` 只能用于本机开发，生产环境必须设为 `0`。
- `MAIL_PASS` 是 SMTP 授权码，不是邮箱登录密码。
- 不要提交 `.env`。
- 模型不可用时不得返回伪造结果，系统应显示降级状态。

### 5.3 启动后端

```powershell
cd harmonyosapp/NexcoreGraph_harmonyos/backend
npm install
node server.js
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3000/api/health
```

期望至少包含：

```json
{
  "ok": true,
  "mode": "lan-self-hosted",
  "ai": "ready"
}
```

### 5.4 可选启动跨设备流转

```powershell
cd harmonyosapp/NexcoreGraph_harmonyos/backend
node flow-bridge.js
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3100/api/health
```

流转服务不是登录、库存、预警和 AI 的必需依赖；只测试跨设备流转时启动。

### 5.5 构建小程序

```powershell
cd wxminiapp/NexcoreGraph_wxminiapp
npm install --legacy-peer-deps
npm run build:weapp
```

首次安装若不加 `--legacy-peer-deps`，Taro 4.1.9 的 Webpack peer 依赖可能产生冲突。

构建产物必须位于 `dist/`，至少检查：

```powershell
Test-Path dist/app.json
npm run typecheck
npm test
```

### 5.6 打开微信开发者工具

1. 打开微信开发者工具。
2. 导入 `wxminiapp/NexcoreGraph_wxminiapp`。
3. 工程已配置 `miniprogramRoot: "dist/"`。
4. 编译后首个页面为 AI 工作台。

本机调试建议在 `project.private.config.json` 中保持：

```json
{
  "setting": {
    "urlCheck": false,
    "compileHotReLoad": false
  }
}
```

`project.private.config.json` 是本地文件，不应作为正式产物上传。

不要一边运行 `npm run dev:weapp -- --watch`，一边让微信开发者工具对同一 `dist/` 自动热重载。两者同时写目录时会出现 `dist/app.json` 丢失或模拟器启动失败。

推荐顺序固定为：

```text
关闭/暂停开发者工具自动热重载
→ 执行 npm run build:weapp
→ 确认 dist/app.json 存在
→ 在开发者工具点击“编译”
```

## 6. 局域网演示

### 6.1 获取后端电脑 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.PrefixOrigin -ne 'WellKnown' } |
  Select-Object InterfaceAlias,IPAddress
```

只选择真实 WLAN/以太网地址，不要使用 VMware、VirtualBox 等虚拟网卡。

### 6.2 放行端口

仅演示环境可在 Windows 防火墙放行 3000 和 3100：

```powershell
New-NetFirewallRule -DisplayName "NexcoreGraph API 3000" `
  -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow

New-NetFirewallRule -DisplayName "NexcoreGraph Flow 3100" `
  -Direction Inbound -Protocol TCP -LocalPort 3100 -Action Allow
```

公网服务器不能照搬此规则，公网只开放 80/443。

### 6.3 手机验证

手机浏览器打开：

```text
http://<电脑局域网IP>:3000/api/health
```

能返回 JSON 后，在小程序“我的 → 服务器连接”填写同一地址。

常见失败：

- 校园网或公共 WiFi 开启客户端隔离。
- Windows 防火墙未放行。
- 手机与电脑不在同一网段。
- 使用了虚拟网卡 IP。

## 7. 公网正式部署

### 7.1 推荐拓扑

```text
微信用户
  → HTTPS 443
  → Nginx
      → 127.0.0.1:3000 Node API
      → 127.0.0.1:3100 可选 flow-bridge
  → MySQL 127.0.0.1:3306
```

服务器建议：Ubuntu 22.04 或 24.04，2 核 2G 起步。3307/3306 和 3000/3100 只监听本机或安全组内网。

### 7.2 创建数据库和专用账号

```sql
CREATE DATABASE nexcoregraph
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'nxg_app'@'127.0.0.1' IDENTIFIED BY '<强随机密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
  ON nexcoregraph.* TO 'nxg_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

不要使用 root 运行应用。

### 7.3 生产环境变量

```text
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=nxg_app
DB_PASSWORD=<强随机密码>
DB_NAME=nexcoregraph

AUTH_SHOW_CODE=0
AI_RPM=20
AI_TIMEOUT_MS=30000

AGNES_BASE_URL=https://api.agnes-ai.cn/v1
AGNES_API_KEY=<服务端密钥>
AGNES_MODEL=agnes-3.0-flash
AGNES_MODEL_ALT=agnes-2.5-flash
AGNES_VISION_MODELS=agnes-2.5-flash,agnes-3.0-flash

WX_APPID=wx25e3afb6ce695963
WX_SECRET=<微信小程序 AppSecret>

MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_USER=<发件邮箱>
MAIL_PASS=<SMTP 授权码>
```

如果需要远端 TTS，再添加：

```text
TTS_ENDPOINT=<HTTPS TTS 服务地址>
TTS_API_KEY=<TTS 密钥>
```

### 7.4 systemd 守护

`/etc/systemd/system/nexcoregraph-api.service`：

```ini
[Unit]
Description=NexcoreGraph API
After=network.target mysql.service

[Service]
Type=simple
User=nexcoregraph
WorkingDirectory=/opt/nexcoregraph/backend
EnvironmentFile=/opt/nexcoregraph/backend/.env
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now nexcoregraph-api
sudo systemctl status nexcoregraph-api
```

需要流转服务时，为 `flow-bridge.js` 建立单独 unit，或将 3100 作为内部服务由同一 systemd 环境管理。

### 7.5 Nginx 反向代理

```nginx
server {
    listen 80;
    server_name api.example.com;
    client_max_body_size 10m;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /tts/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

使用 Certbot 申请证书：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d api.example.com
sudo nginx -t
sudo systemctl reload nginx
```

公网防火墙：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

不要开放 3000、3100、3306 给公网。

## 8. 微信公众平台配置

登录微信公众平台，选择小程序 `wx25e3afb6ce695963`。

### 8.1 服务器域名

在“开发管理 → 开发设置 → 服务器域名”中配置：

| 类型 | 填写 |
|---|---|
| request 合法域名 | `https://api.example.com` |
| downloadFile 合法域名 | 使用 TTS 音频时填写同一 HTTPS 域名 |
| uploadFile 合法域名 | 当前端侧无文件上传；后续启用时再配置 |

域名要求：

- HTTPS；
- 证书链完整；
- 中国大陆服务器域名按要求完成备案；
- 不能填写 IP、localhost 或非 443 端口。

本机 `127.0.0.1:3000` 只允许通过开发者工具“不校验合法域名”使用，不能用于正式版。

### 8.2 服务类目与隐私

按实际能力选择“工具/生活服务”等类目。隐私保护指引至少声明：

- 相机：拍摄物品、小票和储物空间。
- 相册：选择已有照片。
- 文件：导入/导出 CSV。
- 麦克风：仅在启用语音录入时声明。
- 账号标识：登录、家庭空间和同步。
- 用户内容：库存、采购、家庭协作名称。

小程序内需保留 AI 生成内容标识、数据导出、清空本机数据和账号退出入口。

### 8.3 内容安全

生产环境配置 `WX_APPID` 和 `WX_SECRET`，使后端能够调用微信内容安全检查。

检查原则：

- 用户自定义文本先检查；
- 模型输出展示前再检查；
- 微信接口不可用时保留本地兜底，但日志明确记录“未完成远端检查”；
- 不把内容安全失败伪装成模型回答。

### 8.4 订阅消息

在“订阅消息”中申请：

- 临期提醒；
- 采购提醒；
- 家庭邀请。

模板 ID 不得写死在公开源码中。当前项目在未配置模板时会明确提示“未开启”，不能显示假成功。

## 11. 数据备份与恢复

每日备份：

```bash
mysqldump --single-transaction --routines --triggers \
  -h 127.0.0.1 -u nxg_app -p nexcoregraph \
  | gzip > /var/backups/nexcoregraph-$(date +%F).sql.gz
```

建议保留 7 个日备份、4 个周备份。至少每季度做一次恢复演练。

恢复：

```bash
gunzip -c /var/backups/nexcoregraph-2026-11-11.sql.gz |
  mysql -h 127.0.0.1 -u nxg_app -p nexcoregraph
```

审计表 `event_journal` 属于业务历史，不允许通过“清理测试数据”误删生产记录。需要清理测试家庭时，先按精确 `family_id` 查询并导出。

## 12. 日志与监控

最低监控项：

| 指标 | 来源 | 告警建议 |
|---|---|---|
| `/api/health` | Node | 连续 3 分钟失败告警 |
| HTTP 5xx | Nginx access/error log | 5 分钟超过 5 次告警 |
| AI 502/429 | 后端日志 | 连续 3 次提示模型额度或密钥问题 |
| MySQL 磁盘 | 系统监控 | 使用率超过 80% 告警 |
| 备份文件 | 定时任务 | 当天没有新备份告警 |
| 事件链校验 | `/api/events/verify` | 返回 409 立即停止写入并排查 |

日志不得记录完整 API Key、SMTP 授权码、用户验证码或完整会话 token。

## 13. 常见故障

| 现象 | 根因 | 处理 |
|---|---|---|
| `url not in domain list` | 开发校验开启或后台域名未配置 | 本地关闭校验；正式配置 HTTPS 白名单 |
| `dist/app.json` 不存在 | DevTools 热重载与 Taro 构建同时写目录 | 关闭 `compileHotReLoad`，重新 `build:weapp` |
| 模拟器欢迎页不动 | 项目未编译或打开路径错误 | 确认 `miniprogramRoot=dist/`，点击“编译” |
| 手机打不开后端 | 使用了 127.0.0.1 或虚拟网卡 IP | 改真实局域网 IP，检查防火墙 |
| 模型 502 | 上游错误或 Key 不可用 | 检查网关日志、Key、额度和模型名 |
| 模型 429 | 厂商限流 | 降低请求频率，恢复额度，保留本地降级 |
| 登录无验证码 | 邮件通道未配置 | 配置 SMTP；本地临时设 `AUTH_SHOW_CODE=1` |
| CSV 导出失败 | 开发者工具不支持 `shareFileMessage` | 使用真机预览复核 |
| TTS 返回 501/502 | 未配置 TTS 或音频域名 | 配置 `TTS_ENDPOINT`、HTTPS 和 downloadFile 域名 |
| MySQL 启动失败 | 库未创建、账号无权限、端口错误 | 检查 DB_* 环境变量和 3307/3306 监听 |
| 审计链校验失败 | 事件被手工修改或链不连续 | 立即停止新写入，备份数据库，定位 `brokenAt` |

## 14. 回滚

### 代码回滚

1. 停止 systemd 服务。
2. 切换到上一个已验证提交或发布包。
3. 执行 `npm ci`。
4. 运行 `node --check server.js`。
5. 启动并检查 `/api/health`。
6. 对小程序的体验版执行一次主流程回归。

### 数据回滚

优先恢复整库备份。不要只恢复部分业务表后继续使用旧的 `event_journal` 哈希链。

如果只发生错误业务数据写入，优先通过业务补偿事件撤销，而不是直接修改历史事件。

### 小程序版本回滚
