### 顺带发现并修复：AI 把"思考过程"原样显示给了用户

平板上的实测回复长这样（端侧原样展示，很难看，也泄露内部提示措辞）：

```
[思考过程：用户询问“药盒”。我需要检查库存摘要。… 回复策略：… 回复内容：当前库存中没有“药盒”的记录。…
```

已修：① 系统提示里明确要求"直接给结论，不要输出思考过程/推理步骤/回复策略"；
② 后端加 `stripReasoning()` 兜底（裁到"回复内容："之后的正文，并清掉残留方括号）。
复测：同一条提问返回干净正文（"记录中没有药盒的位置信息…药盒里现在有 1 盒布洛芬，30 天后到期"）。

## 五、已知小问题（不影响主流程）

1. **multi-hop 图谱证据在数据量小时为空**：端侧对"做饭/采购"类意图固定请求 multi-hop，但库里只有 1 件物品时返回 0 条证据（后端日志 `mode=multi-hop lines=0`）。建议端侧在证据为空时自动降级到 local 模式，或在提示里说明"证据不足"。
2. 首页空态文案写"你的库还是空的"，实际可能是"有库但没物品"；建议按 `libraries.length === 0` 与 `items === 0` 分开措辞。

## 六、2026-10-16 复测 A：库类型不设限

测试环境：同一台 Mate 80 Pro Max 模拟器（1320×2848）+ 自建后端（真 Key，真模型）；操作全部在界面上完成，截图见作品介绍文档 5.9。

| 复测项 | 实测证据 |
|---|---|
| 建库不限于食材 | 资源库 → 新建库 → 名称输"厨具柜" → 图标选新增的厨具图标 → 创建成功，"2 个库"变"3 个库" |
| 入库目标库可选 | 在厨具柜里点"拍照入库" → 从相册选一张蔬菜照片 → 结果卡片上方出现「入库到：冰箱 / 药盒 / 厨具柜」，默认高亮**厨具柜**（你打开的那个库） |
| AI 真实识别 | 同一张照片识别出"胡萝卜 4 根 / 冷藏区 / 14 天 / ¥35.00"，来源标"拍照识别（AI 生成）"；确认入库后厨具柜从"全部 1"变"全部 2" |
| 非易耗品不进临期 | 厨具柜里手动加的"炒锅"（保质期留空）标**无保质期**，同库里"临期 0"；首页临期计数仍为 0 |
| 冷链筛选项按需出现 | 厨具柜没有冷藏物品时不显示"冷藏/冷冻"按钮；加入胡萝卜（位置=冷藏区）后出现"冷藏 1" |
| 拍照页与失败文案 | 拍照页显示"拍一张照片 · 冰箱 / 衣柜 / 工具箱都可以"；空结果提示改为"换成冰箱、衣柜、工具箱、厨具架、购物袋这类照片更准" |

本轮改掉的真实缺陷：

1. **入库目标库写死**：`addItems()` 固定写 `store.libraries[0]`（第一个库，实际就是"冰箱"），衣柜、工具箱、厨具柜建了也永远收不到 AI 识别的物品。
   现在入库带目标库参数，确认前可选择；一个库都没有时按识别出的类别自动建库。
2. **非易耗品被塞 7 天保质期**：识别结果 `expDays` 缺失/为 0 时被补齐成 7，且 7 处 `expDays <= 7` 的判断漏了 `> 0`，
   于是衣物、工具、厨具入库后立刻变成"7 天后到期"的临期品，还进服务卡片与首页焦点区。现在 0 表示"不适用"，全链路一致。
3. **入库提示条数算错**：toast 在 `resetIntake()` 之后才统计 `store.intake`，永远显示"已入库 0 项"；改为入库前取数，并带上目标库名（"已入库 1 项到「厨具柜」"）。

命令表在 `common/Commands.ets`，对话页「指令手册」与解析器共用同一份定义；启动时自检手册里每句话是否真能命中。
界面截图见作品介绍文档 5.10（图 5-18 指令手册 / 图 5-19 对话里由本地指令接住）。

| 复测项 | 实测证据 |
|---|---|
| 手册自检 | hilog：`cmd selfcheck: 手册自检 22/22 可命中`（22 条示例全部能被指令层或意图快答接住） |
| 建库 | 说"帮我建一个工具柜库" → 回复"建好了「工具柜」。接着说「往工具柜加一把螺丝刀」…"，来源标"本地指令 · 0 次模型调用"，同时自动切到资源库 |

| 列库存 | 说"库存里都有什么" → 分库清单（冰箱 1 件 / 药盒空 / 厨具柜 3 件 / 工具柜空），数字与资源库一致 |
| 主题切换 | 说"换成深色主题" → "换成深色了"（截图核对：界面确实变深色）；说"换回浅色主题" → "换回浅色了。"（恢复浅色） |

本轮修掉的两个真实缺陷（都是实测撞出来的）：

1. **`换回浅色主题` 命中不了**：主题正则的连接词只写了"成/为/到"，用户说"换回/换至"就落到模型路——模型会礼貌地回答"已为您换回浅色主题"，
   但界面根本没变（模型没有改主题的能力）。补上"回/至"后由指令层接住，回复与界面一致。
2. **确认卡点完不消失、结果不显示**：`ChatMsg` 是普通类（要整块进同步 DTO，不适合加观测），改完字段后
   `store.chat = store.chat.slice()` 不会让这一条重绘——按钮留在原地，用户以为没生效。改为"换实例 + 版本号 +1"，
   ForEach 的 key 带上版本号（同一处理也补给了原有的"应用调整/加入采购清单"按钮）。
