# 启核图策 NexcoreGraph Web 端 · 高分口播与操作手册

> 版本：2026-11-11
> 正式演示：约 7 分 10 秒
> 电梯演示：90 秒
> 目标：让评委在两分钟内看懂技术差异，在中段看到创新证据，在结尾看到完整工程闭环。

## 一、先记住这三句话

1. **不是“库存表 + 聊天框”，而是从临期事实到今晚行动的决策执行系统。**
2. **模型负责理解与解释，代码负责事实、约束、求解和权限。**
3. **推荐不是黑盒：每个结果都能看到证据、分数来源、淘汰原因和撤销入口。**

正式演示中，这三句话要在开场、中段和收尾各出现一次。

## 二、开录前检查

### 1. 启动后端

```powershell
cd D:\ProjectFiles\GithubPackage\NexcoreGraph\harmonyosapp\NexcoreGraph_harmonyos\backend
npm start
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3000/api/health
```

看到：

```json
{"ok":true,"mode":"lan-self-hosted","ai":"ready"}
```

### 2. 启动 Web

另开终端：

```powershell
cd D:\ProjectFiles\GithubPackage\NexcoreGraph
python tools/serve_web.py --root web/NexcoreGraph_web --port 8080
```

打开：

```text
http://127.0.0.1:8080/
```

### 3. 浏览器和录屏

- Edge 或 Chrome。
- 窗口 `1600×1000`，缩放 100%。
- 关闭通知、书签栏、无关标签、输入法弹窗。
- 1080p，30fps。
- 打开鼠标点击高亮。

### 4. 数据与素材

- 正常邮箱登录；不准备固定公开验证码。
- 至少准备 3 种临期食材，如鸡蛋、牛奶、番茄。
- 准备一张冰箱/食品柜照片。
- 建议录屏前完成一次登录，避免验证码等待影响节奏。
- AI 上游可能限流；必须预演“AI 失败继续演示规则能力”的分支。

### 5. 安全预检查

```powershell
curl.exe -I http://127.0.0.1:8080/.env
```

必须是 `404`。如果返回 `200`，立即停止演示并更换安全静态服务器。

## 三、7 分钟正式演示分镜

### 第 0 段：开场定调｜0:00–0:25

**画面**

- 登录页或 AI 工作台。

**操作**

- 登录后停留在 AI 工作台。
- 鼠标从左到右缓慢划过摘要、待办和“今晚先救哪几样”。

**口播**

> 家庭里真正难的不是“不知道冰箱有什么”，而是知道快过期了，却仍然不知道该先做什么。启核图策做的不是库存表加聊天框，而是从临期事实出发，自动完成判断、规划、确认、执行和撤销。模型负责理解，代码负责事实和约束。

### 第 1 段：AI 工作台｜0:25–0:55

**操作**

1. 指一下“今晚先救哪几样”。
2. 指出 Top 2 推荐和“Pareto + 组合求解 · 0 次模型调用”。
3. 点击“打开救援驾驶舱”。

**口播**

> 系统一进入就主动告诉我今晚最值得处理什么。注意这里的结果不是大模型随口推荐的，而是求解器基于真实库存计算出来的；即使模型断流，这条主流程仍然可用。

### 第 2 段：核心技术总览｜0:55–1:30

**画面**

- 救援驾驶舱首屏。

**操作**

1. 鼠标依次划过四个指标：临期食材、可救回估值、Pareto 前沿、累计救回。
2. 指向“今晚救援菜单”和“组合求解”。
3. 鼠标移到第一张卡的“救援分”和“PARETO”。

**口播**

> 这一屏是项目的核心技术。系统同时优化临期覆盖、食材匹配、缺料数量、烹饪时间、营养和救回价值。普通推荐只给一个分数，我们还计算 Pareto 非支配集，告诉评委哪些方案是真的权衡，哪些只是被其他方案全面支配。

**关键词必须说清**

- 多目标优化
- Pareto 非支配
- 约束组合
- 可解释得分

### 第 3 段：反事实沙盘｜1:30–2:20

**操作**

1. 点击时间“15 分钟”。
2. 点击“最快开饭”。
3. 点击“2 道”。
4. 在“反事实排除”选择一个食材。
5. 鼠标停住，让候选和组合菜单重新排序。

**口播**

> 现在做一次反事实推演：如果今晚只有十五分钟，或者家里有人不吃某样食材，会发生什么？系统不是重新问模型，而是重新计算约束空间。候选、组合菜单、缺料和总时长会同步变化，这就是可交互的决策沙盘。

**加分点**

- 同一个问题的 what-if 分析。
- 不是静态推荐卡。
- 不需要重新调用模型。

### 第 4 段：推荐依据与决策回放｜2:20–2:55

**操作**

1. 点击任一候选的“查看依据与做法”。
2. 指出“推荐依据”三条。
3. 指向“消耗食材”和“做法”。
4. 指向底部的 AI 边界说明。

**口播**

> 推荐必须可审计。这里能看到库存匹配了几种、哪几项临期、得分由哪些部分贡献，还能看到淘汰原因和实际做法。模型不能改库存数字，也不能把没有的证据编出来；它只负责把代码算出的决策组织成自然语言。

### 第 5 段：组合菜单与写操作确认｜2:55–3:40

**操作**

1. 关闭抽屉。
2. 点击“预览这套菜单”。
3. 指向每道菜、当前库存、缺料和“确认前不会扣减库存”。
4. 点击“确认并执行”，等待完成。

**口播**

> 这不是只生成一段菜谱文字，而是生成可执行的组合菜单。系统先给出预览，明确告诉我缺什么、会消耗什么；确认前绝不扣库存。所有写操作都走预览、确认、执行、撤销和审计日志。

### 第 6 段：撤销与恢复｜3:40–4:05

**操作**

1. 进入“全部方案”或方案页。
2. 找到刚执行的方案。
3. 点击“撤销”。
4. 回到资源库，指出数量恢复。

**口播**

> AI 执行错误并不可怕，关键是能不能恢复。刚才的操作已经写入审计日志和库存快照，一键撤销后，数量回到执行前。我们把“可撤销”做成了系统能力，而不是提示用户自己记住。

### 第 7 段：GraphRAG 与证据链｜4:05–4:50

**操作**

1. 打开“资源图谱”。
2. 点一个临期物品节点。
3. 展示节点、边、路径或来源。
4. 回到 AI 工作台问一个库存问题，例如“鸡蛋放哪了”或“牛奶还能放几天”。
5. 指向回答下方的证据来源。

**口播**

> 库存在这里不是一张平表，而是一张个人资源知识图谱。它会建立物品、库位、食材概念、菜谱和缺料之间的关系。回答前先检索证据，回答后显示来源和路径。不是把库存整段塞给模型让它猜。

### 第 8 段：AI 边界与降级｜4:50–5:20

**口播备用版**

> 如果模型服务正常，继续展示回答和来源。如果遇到 429 或 500，不切掉这段，直接指出系统显示“本地降级 · 0 次模型调用”，并继续使用 GraphRAG 事实和确定性救援结果。这个失败分支本身是可靠性证据：我们不伪造模型成功。

**操作**

- 如果正常：让回答出现，指向模型名和来源。
- 如果失败：指向“Agnes 暂不可用”和本地图谱统计。

### 第 9 段：多模态入库｜5:20–6:00

**操作**

1. 打开“拍照入库”。
2. 上传冰箱或食品柜图片。
3. 识别成功时，指出名称、数量、位置、保质期、价格。
4. 不急确认，停 2 秒。
5. 点击确认入库。

**口播**

> 多模态入口把现实世界转成结构化事实。识别只给候选，字段来源可见；缺失字段由用户补，确认后才入库。如果识别失败，系统会明确提示，而不是编造一个看似完整的库存结果。

### 第 10 段：真实资源操作｜6:00–6:30

**操作**

1. 打开资源库。
2. 数量 `+1`，再 `−1`。
3. 手动添加一件物品。
4. 打开全局搜索，搜索刚添加的物品。

**口播**

> AI 不是演示孤岛。库存增减、手动新增和搜索都走同一套状态层。推荐能落到真实操作，操作又能回到下一次推荐，这是完整的业务闭环。

### 第 11 段：工程与安全收尾｜6:30–7:10

**操作**

1. 回到救援驾驶舱。
2. 让画面停在 Pareto 和组合菜单。

**口播**

> 最后总结三个创新点：第一，确定性多目标救援求解，保证没有模型也能做决策；第二，反事实沙盘和决策回放，让推荐可以被追问；第三，受控 Agent 闭环，让建议真正执行又可撤销。启核图策把“快过期了”变成“今晚怎么做，以及做完怎么恢复”。

### 0:15–0:40

> 我们用确定性多目标求解器同时考虑临期程度、库存匹配、缺料、时间和营养，并计算 Pareto 非支配集。

> 推荐能一键变成计划，执行前必须确认，执行后可撤销并留下审计记录。

## 六、评委追问的标准回答

### “这是不是一个套壳大模型？”

> 不是。库存、日期、缺料、评分、Pareto、组合约束和救回价值全部由代码计算。模型只做自然语言理解和解释，没有权限直接写库存。

### “为什么不用一个加权总分就结束？”

> 加权分数适合排序，但会掩盖不同目标之间的冲突。Pareto 前沿保留互不支配的方案，让用户看到“更快”与“更多覆盖”之间的真实权衡。

### “AI 挂了怎么办？”

> 核心救援求解不依赖模型。模型不可用时，系统会明确显示本地降级和 0 次模型调用，并继续返回图谱事实与确定性推荐。

### “推荐错了会不会改坏库存？”

> 不会。写操作必须先预览，用户确认后才执行；执行会保存快照，支持撤销并写审计日志。

### “为什么叫 Agent，而不是聊天机器人？”

> 因为它有意图识别、证据检索、受约束工具、确认门、执行和撤销链。聊天只是入口，行动才是结果。

### “创新点到底是什么？”

> 把临期推荐从单目标排序升级为多目标非支配求解，再加上反事实沙盘、组合菜单和决策回放。用户不仅能得到结果，还能理解结果为什么成立。

### “商业和落地价值是什么？”

> 直接减少食材浪费，降低重复采购，把家庭库存转成可执行计划。相同架构还能扩展到药品、耗材、衣物和工具。

## 七、失败分支也要讲得漂亮

### 视觉模型失败

> 识别服务当前失败，系统没有伪造库存结果。我们继续展示人工确认和规则推荐；这正是多模态链路与事实层解耦的价值。

### 文本模型 429/500

> 上游限流了，页面已经明确标注本地降级。接下来展示的是 0 次模型调用的确定性求解，也是我们刻意保留的离线能力。

### 网络断开

> 断网时主流程仍能读取本地状态，执行和撤销继续工作；联网能力失败不会破坏事实一致性。

## 八、演示禁止事项

- 不说“100% AI 自动”，因为写操作必须确认。
- 不说“模型不会出错”，只说失败会被标识并可降级。
- 不把测试截图说成真实家庭数据。
- 不展示真实 API Key、验证码、邮箱授权码。
- 不用 `python -m http.server` 暴露工程目录。
- 不在 AI 上游失败时假装成功。
- 不说当前已经部署公网，除非现场 URL 真的可访问。
