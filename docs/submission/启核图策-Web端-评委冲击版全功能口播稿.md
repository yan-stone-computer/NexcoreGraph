# 启核图策 Web 端 · 评委冲击版全功能口播稿

> 版本：2.0
> 日期：2026-11-11
> 正式版：8 分钟整
> 救场版：60 秒
> 适用：作品演示视频、现场答辩、评委巡展讲解

## 一、主叙事

**别人记录家里有什么，我们计算下一步该做什么，并让每个动作都可约束、可解释、可撤销。**

**模型可以替换，事实、约束和权限不能替换。**

全片用一条家庭决策链串起所有功能：

> 看见资源 → 形成事实 → 构建图谱 → 推演风险 → 多目标决策 → 用户确认 → 执行与撤销 → 审计复盘

不要按左侧菜单逐个念功能。每进入一个模块，都回答一个问题：

- 它解决了什么真实问题？
- 它的技术难点是什么？
- 评委现场能看到什么证据？

## 三、8 分钟正式口播

### 00:00–00:25｜开场：先夺注意力

**画面**

- AI 工作台。
- 镜头从“今晚先救哪几样”缓慢拉到临期统计和 Top 2 推荐。

**操作**

- 登录后停在 AI 工作台。
- 鼠标划过摘要、主动待办、临期统计和救援入口。

**口播**

> 评委老师，大多数家庭应用在问：家里现在有什么？
>
> 启核图策想回答一个更难的问题：接下来七天，哪些东西会先过期？今晚究竟该先做什么？
>
> 我们做的不是库存表加聊天框，而是一套从家庭事实到可执行决策的智能系统。模型负责理解，代码负责事实、约束和权限。

**字幕**

> 从“记录资源”到“执行下一步”

### 00:25–00:55｜AI 工作台：主动智能

**操作**

1. 指一下待确认队列。
2. 指一下实时统计。
3. 指向“今晚先救哪几样”和 Top 2 菜名。
4. 指出“Pareto + 组合求解 · 0 次模型调用”。

**口播**

> 登录后的第一屏不是功能菜单，而是 AI 工作台。
>
> 系统主动把临期食材、低库存、待确认动作和下一步菜单放到我面前。这里最关键的是：核心排序不是模型随口生成，而是本地确定性求解。即使模型断流，主动推荐仍然成立。

**评分点**

- AI 原生入口。
- 主动智能。
- 0 次模型调用快路径。

### 00:55–01:40｜多模态入库：让现实世界进入系统

**操作**

1. 打开“拍照入库”。
2. 上传冰箱或食品柜照片。
3. 识别成功后，依次指名称、数量、位置、保质期、价格和置信度。
4. 停留 2 秒，不要急着确认。
5. 点“确认入库”。

**口播**

> 第一步是让现实世界进入系统。
>
> 上传一张照片，视觉模型输出结构化候选：名称、数量、存放位置、保质期和价格。注意，模型只负责“候选”，缺失字段由人补，价格和日期来源可见。
>
> 用户点击确认之前，库存不会发生变化。这是多模态能力，也是 AI 写入边界。

**失败备用**

> 如果识别服务当前失败，系统会明确提示，而不是伪造一个完整结果。我们继续演示补录和确认链路；AI 失败不会破坏事实一致性。

### 01:40–02:10｜资源库与搜索：完整业务底座

**操作**

1. 打开资源库。
2. 对一个食材数量 `+1`，再 `−1`。
3. 点击“手动添加”，新增一件测试物品。
4. 打开全局搜索，搜索刚添加的物品。

**口播**

> AI 不是演示孤岛。
>
> 库存增减、手动新增、编辑和跨库搜索都走同一套状态层。推荐可以落到真实库存，真实操作又会进入下一次推荐。这是完整的业务闭环，而不是一张只能看的推荐卡。

### 02:10–02:40｜看板、预警与采购：把数据变成待办

**操作**

1. 打开首页看板。
2. 指出临期数、低库存、健康度和趋势。
3. 点击右上角铃铛，展示预警中心。
4. 点击采购车，展示缺料与低库存合并清单。

**口播**

> 看板上的数字全部由代码实时计算，不由模型生成。
>
> 临期、低库存、药品期限和保修期统一进入预警中心；方案缺料和低库存自动合并为采购清单。数据不是终点，而是下一组动作。

### 02:40–03:35｜家庭智策：不是只服务食品

**操作**

1. 打开左侧“家庭智策”。
2. 在全景卡中依次指药箱、健身、工具箱。
3. 打开“药箱”：指出临期药、过期药、低库存和补货提示。
4. 打开“健身”：输入身高、体重、年龄、目标、水平和每周天数。
5. 点击“生成训练方案”，展示 BMI、目标心率、器材覆盖和三天训练安排。
6. 打开“工具家电”：指出电钻剩余保修 12 天、借给邻居、1 天后归还。
7. 快速切到“生活资产”：扫过衣橱、家电、书籍、宠物用品和清洁耗材。
8. 回到“全景”：指出全屋资源、估值、生活资产和跨域风险汇总。

**口播**

> 启核图策不是只围绕食品。我们把家庭资源抽象成统一事实模型，再为不同生活域配置不同算法。
>
> 药箱关心有效期、过期药和常用药补货；工具和家电关心保修、维护、借用人以及归还倒计时；健身模块把身高、体重、年龄、目标、训练水平和现有器材作为约束，计算 BMI、目标心率和每周训练方案。没有哑铃时自动退化为自重训练。
>
> 全屋视图再把衣橱、家电、书籍、宠物用品和清洁耗材拉进同一事实层，计算数量、估值、低库存和临期风险。所有场景共用库存、权限和审计底座，但每个领域都有独立的业务逻辑。

**弹幕字幕**

> 食品不是全部：药箱 · 健身 · 工具 · 衣物 · 家电

### 03:35–04:10｜GraphRAG：个人资源知识图谱

**操作**

1. 打开“资源图谱”。
2. 点击一个临期物品节点。
3. 展示物品、库位、类别概念、菜谱和来源路径，可点一个药品或工具节点说明非食品同样进入图谱。
4. 回到 AI 工作台问“鸡蛋放哪了”，指向证据来源。

**口播**

> 库存在这里不是一张平表，而是一张个人资源知识图谱。
>
> 系统把物品、库位、食材概念、菜谱和缺料关系连接起来。问题进来后，先检索证据，再让模型组织语言；回答下方可以追到库位、来源和路径。不是把整段库存塞给模型，让它自己猜。

### 04:10–05:00｜临期救援：多目标 Pareto 求解

**操作**

1. 打开“临期救援驾驶舱”。
2. 依次指四个 KPI。
3. 指向“今晚救援菜单”和组合求解次数。
4. 指向第一张候选的“救援分”和“PARETO”。
5. 指向评分贡献条。

**口播**

> 这是项目最核心的技术之一。
>
> 普通推荐只给一个分数，我们同时优化临期覆盖、食材匹配、缺料数量、烹饪时间、营养和救回价值。
>
> 加权分数用于排序，Pareto 前沿用于保留真正互不支配的方案。这样评委能看到“更快”和“覆盖更多”之间的技术权衡，而不是被一个黑盒总分掩盖。

**技术暴击句**

> 不是让模型猜数字，而是让代码把数字算死。

### 05:00–05:35｜反事实沙盘：不是调提示词，而是重算约束

**操作**

1. 点击时间“15 分钟”。
2. 切换“最快开饭”。
3. 改为“2 道”。
4. 在“反事实排除”里选择一种食材。
5. 鼠标停住，让候选和组合菜单重排。

**口播**

> 如果今晚只有十五分钟，或者家里有人不吃某样食材，会发生什么？
>
> 系统不会重新问模型，它会重新计算约束空间。候选、缺料、组合菜单和总时长同步变化。这是一个可交互的反事实决策沙盘。

**字幕**

> What-if：同一个问题，不同约束，不同最优解

### 05:35–06:00｜决策回放：推荐为什么成立

**操作**

1. 点击“查看依据与做法”。
2. 展示“推荐依据”三条。
3. 展示匹配食材、缺料、步骤和替代建议。
4. 指向“AI 只解释代码结果”的说明。

**口播**

> 我们不仅给推荐，还让推荐可以被追问。
>
> 这里能看到库存匹配了几种、哪几项临期、得分由哪些部分贡献、为什么被淘汰，以及实际做法。模型不能改库存数字，也不能把没有的证据编出来。

### 06:00–06:30｜受控 Agent：预览、确认、执行、撤销

**操作**

1. 打开 AI 面板。
2. 输入“鸡蛋还剩 5 个”或点击官方示例。
3. 展示库存调整预览卡。
4. 点击确认。
5. 回到资源库查看数量变化。
6. 在方案页或设置中点击撤销。

**口播**

> Agent 不是一个会聊天的文本框。
>
> 当我说“鸡蛋还剩五个”，模型不会直接改库。系统先生成一张确认卡，展示旧值和新值；确认后才执行，并保存快照。执行错了可以撤销，操作全程写审计日志。
>
> 这里有四道门：工具白名单、角色权限、用户确认和幂等执行。

### 06:30–06:55｜家庭协作：同一份家庭事实

**操作**

1. 打开“协作工作台”。
2. 展示邀请码、成员手牌和协作池。
3. 如果环境已准备双窗口，在另一窗口展示同步变化。
4. 指一下同步状态或版本号。

**口播**

> 家庭不是单用户场景。
>
> 管理员、成员和只读角色拥有不同权限；成员通过邀请码加入协作工作台，共享的是一份带版本号的家庭事实。写操作、撤销和冲突二选一都可追踪。

### 06:55–07:15｜管理员端：AI 也要被治理

**操作**

1. 切换到预先登录好的管理员标签页。
2. 展示用户管理、家庭容量、AI 用量、模型配置和知识库版本。

**口播**

> AI 不只要能用，还要能被治理。
>
> 管理员端可以看到 AI 调用次数、费用、路由分布和限流，管理知识库版本、模型配置和家庭权限。模型不是系统外的黑盒，而是被配额、日志和版本控制的工程组件。

### 07:15–07:35｜工程与安全：不是一次碰巧的 Demo

**操作**

1. 切回救援驾驶舱。
2. 画面叠加测试与安全证据字幕。

**口播**

> 这些能力不是靠一次现场运气。
>
> 我们有求解器单元测试、真实浏览器端到端、移动端和平板回归；安全静态服务拒绝 dotenv、目录列表和路径穿越；模型失败会明确降级，不伪造结果。
>
> 核心事实、排序和预算逻辑都可在没有模型 Key 时复现。

**字幕证据**

> Web 单测 21/21 · 真实操作多轮通过 · 控制台异常 0 · .env 返回 404

### 07:35–07:52｜多平台模型：不把项目锁死在一个厂商

**操作**

1. 打开“设置 → 服务器连接 · AI 通道”。
2. 点 DeepSeek，展示 Base URL 和模型自动填入。
3. 点 Claude，展示协议标签切换为 `Anthropic Messages`。
4. 点 Gemini，展示 `Gemini GenerateContent`。
5. 指向自定义 OpenAI 兼容、视觉模型、超时和已保存 Key 的末四位掩码。

**口播**

> 我们没有把比赛作品锁死在一个模型厂商。
>
> 设置页内置 OpenAI、DeepSeek、通义千问、Kimi、Claude、Gemini、智谱和自定义网关模板，实际支持 OpenAI Compatible、Anthropic Messages、Gemini GenerateContent 三种协议。Base URL、文本模型、视觉模型和超时都能手改，也能接 vLLM、Ollama 与企业代理。
>
> Key 只保存在本机并掩码显示，不进入同步快照；生产部署可切回服务端网关。模型下线可以换，上游限流可以降级，但库存事实、安全边界和用户确认权不变。

**评分点**

- 厂商解耦。
- 三种真实协议适配。
- 自定义 Base URL 与模型。
- 密钥掩码和服务端网关双保险。
- 复用团队自有 `NexcoreToolGuard`、`nexcore-context-governor`、`NexcoreMemory` 和 `NexcoreVision` 的工程原则。

### 07:52–08:00｜收尾：拔高但不吹牛

**画面**

- 回到家庭场景，最后停在“救援分 / Pareto / 今晚菜单”。

**口播**

> 从食材、药箱到健身器材和工具，我们从家庭里的真实事实出发，让 AI 看得见、算得清、解释得出、执行得安全，也恢复得了。
>
> 这就是启核图策：让每一个家庭决定都有证据，让每一个 AI 动作都能负责。

## 四、60 秒救场版

> 启核图策不是库存表，而是家庭资源决策系统。
>
> 拍照和视觉把物品变成结构化事实；资源库和全局搜索保证数据可维护；GraphRAG 把物品、库位和菜谱连成个人知识图谱。
>
> 同一套底座还能管理药箱、健身器材和工具：药品按有效期和库存阈值预警，健身模块根据身体数据与现有器材生成训练方案，工具箱按保修和维护周期提醒。
>
> 全屋全景继续覆盖衣橱、家电、书籍、宠物用品和清洁耗材，并把临期、低库存、保修、维护、借出逾期合并为跨域风险队列。
>
> 我们的核心技术是确定性多目标救援求解：临期覆盖、匹配率、缺料、时间和营养一起计算，输出 Pareto 非支配方案和可解释组合菜单。改一个约束，候选就会实时重排。
>
> 最后，AI 动作必须经过预览、权限、确认和幂等校验，执行后可撤销。模型可以解释，但事实和权限永远在代码与用户手里。
>
> 模型通道也不是单一厂商：设置页可切换 OpenAI 兼容、Claude、Gemini 或自定义企业网关，Base URL、模型和 Key 都能配置，换模型不换业务。
>
> 这就是启核图策：把“快过期了”变成“今晚怎么做”，也把“AI 说了什么”变成“为什么可信、能不能负责”。

## 五、加分项清单

| 加分项 | 展示方式 | 为什么加分 |

| 反事实沙盘 | 时间、菜数、排除食材即时变化 | 可交互决策 |
| 决策回放 | 推荐依据、贡献条、步骤 | 可解释 AI |
| 受控 Agent | 预览、确认、执行、撤销 | 写操作安全 |
| 确定性离线能力 | 无模型仍能推荐和执行 | 可靠性 |

## 七、操作安全线

- 不说“100% 自动”，写操作始终由用户确认。
- 不把测试数据说成真实家庭数据。
- 不展示真实 API Key、验证码、SMTP 授权码。
- AI 429/500 时明确说明降级，不假装成功。
- 视觉识别失败时不伪造库存。
- 不把未部署的公网地址说成已经上线。
- 不在现场临时登录管理员端；提前打开并登录第二个标签页。
- 不长时间停留在登录、验证码和等待动画上。

## 八、镜头和字幕建议

- 前 15 秒只保留一个问题和一个结果。
- 每个模块先完成操作，再开口解释。
- 技术结论配 6–12 字字幕，例如“Pareto 非支配”“代码算事实”“先预览后写库”。
- GraphRAG、Pareto 和撤销画面至少停留 1.5 秒。
- AI 失败画面不要剪掉，配上“本地降级 · 0 次模型调用”字幕。
- 真实录屏占比不低于 80%。
- 语速 220–250 字/分钟；技术结论后停 0.4 秒。
