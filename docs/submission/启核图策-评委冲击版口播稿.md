## 一、新版只讲一个判断

普通家庭应用记录“家里有什么”。启核图策推演“未来会发生什么”，再把建议变成可确认、可撤销、可追溯的动作。

旧版容易让评委误以为这是一个食品库存或菜谱应用。新版必须把产品边界讲清：

**食品是入口，不是边界。家庭资源至少包括食品、药品、健身器材和工具。**

核心主张升级为：

> 别人记录家庭资源，我们推演家庭资源，并让 AI 的动作可约束、可验证、可追溯。

四层闭环保持不变，但每一层都覆盖多个资源域：

1. **感知**：扫码、视觉和手动录入把家庭资源变成结构化事实；
2. **推演**：每个资源域使用自己的确定性规则，不再把餐次错误乘到药品和工具上；
3. **行动**：Agent 生成训练、补货、维护或处置建议，写操作必须预览确认；
4. **信任**：策略白名单、幂等守卫、数字核对、证据链和自动评测共同兜底。

**画面**

## 五、60 秒答辩版

> 启核图策不是食品库存表，而是多域家庭资源数字孪生。
> 扫码和视觉把食品、药品、器材和工具变成结构化事实；资源图谱把它们连成关系；不同资源域使用不同规则推演：食品看人数餐次，药品看用户填写的每日用量，健身器材匹配身体数据和现有器材，工具只看可用性与维护。
> 比如 170 cm、68 kg 的用户可以直接生成 BMI 23.5、每周 3 天的训练计划；药品余量不会被来客人数错误放大；工具也不会被当成每天消耗零点零几把。
> AI 不直接改库。工具必须经过白名单、参数、确认和幂等；回答必须带来源、路径和数字证据。
> 模型层支持主流平台和自定义 OpenAI-compatible，Key 只留在服务端。
> 让 AI 从会说，升级到能推演、能执行且可信，这就是启核图策。

## 六、商业落地与增长

### 6.1 目标用户

| 用户 | 核心任务 | 首要价值 |
|---|---|---|
| 年轻家庭 | 食品、药品、工具和器材分散管理 | 一个入口看全家庭资源 |
| 健身与自我管理人群 | 身体数据与家用器材脱节 | 按目标和现有器材生成训练 |
| 老人家庭与照护者 | 药品余量、维护和提醒容易遗漏 | 余量与风险提前暴露 |
| 家政、社区与校园服务 | 多户资源数据难统一 | 私有部署与场景模板 |

### 6.2 商业闭环

- **家庭基础版免费**：本地快答、资源库、基本图谱、确定性孪生；
- **家庭 Pro 订阅**：多成员协作、跨端同步、高级训练与历史分析；
- **BYOK**：用户自带模型 Key，降低平台推理成本；
- **私有部署**：面向家政、养老、校园和社区机构；
- **场景模板**：老人照护、健身家庭、维修爱好者和宿舍模板。

### 6.3 推广路径

- 先以“7 天后会缺什么”的可视化结果做传播；
- 用免费本地能力降低首次体验门槛；
- 用 BYOK 吸引已订阅模型服务的用户；
- 与校园、家政、社区养老做小范围试点；
- 用开源许可证、测试报告和隐私边界建立渠道信任；
- 后续上线应用市场体验版，凭证作为加分材料，未完成前不虚报。

## 九、评委追问

| 追问 | 回答 |
|---|---|
| 这不还是库存管理吗？ | 库存只是事实层；我们增加了多域规则、未来推演、训练生成和受控动作。 |
| 食品、药品、健身、工具为什么放一起？ | 它们共享感知、图谱、确认、同步和审计，但规则不同，是统一底座而非同一公式。 |
| AI 会不会乱改数据？ | 模型无直接写权限；白名单、参数、用户确认、幂等和日志共同守门。 |
| 训练计划是不是模型随便编的？ | 本轮是确定性规则引擎生成，AI 只做解释；相同输入得到相同计划。 |
| 药品安全吗？ | 只复述用户填写的用量，不猜剂量、不做诊断；余量风险只做库存提醒。 |
| 为什么换模型？ | 家庭场景有不同成本、隐私和视觉需求；OpenAI-compatible 适配层避免厂商锁定。 |
| API Key 安全吗？ | Key 只写服务端 `.ai-config.json`，端侧只显示脱敏尾号；修改需管理员令牌，公网必须 HTTPS。 |
| 断网还能用吗？ | 本地快答、资源图谱、规则推演和训练计划不依赖模型。 |
| 为什么引用 GitHub 项目？ | 复用自有 MIT 项目的成熟设计，明确区分已吸收、可适配和未集成。 |

## 十、表达禁区

- 不说“AI 全自动处理家庭事务”；
- 不说“100% 识别准确”；
- 不说“药品 AI 能给出剂量建议”；
- 不说“训练计划可以替代医生或专业教练”；
- 不把服务卡片写成系统通知；
- 不宣称分布式数据对象 DDO 已上线；
- 不宣称所有模型平台已经逐一联网验证；
- 不把尚未嵌入的开源项目写成已完成集成；
- 不在 HTTP 公网环境宣称 API Key 安全；
- 未签名 HAP 不宣称可以上架。

## 十一、剪辑与配音

- 语速 220–250 字/分钟；
- 前 15 秒不提团队、Logo 和登录；
- 每 20–30 秒只强调一个结论；
- 药品和训练段落必须出现真实界面，不使用生成图替代；
