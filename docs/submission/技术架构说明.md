# 启核图策 NexcoreGraph · 技术架构说明

> 日期：2026-11-10
> 赛道：第九届传智杯 AI 鸿蒙赛道
> 工程：`harmonyosapp/NexcoreGraph_harmonyos`

## 1. 项目说明

启核图策是一款面向家庭和多人合住场景的家庭资源智能管家。它把物品从“记在备忘录里的名字和数量”升级为可查询、可推演、可协作的资源图谱，并用 AI 处理扫码、识别、规划、提醒和处置。

### 目标用户

- 有囤货习惯、经常忘记保质期的家庭；
- 多人合住、需要同步库存的宿舍与合租群体；
- 需要管理药品、保修期、工具箱和衣物等多类资源的家庭；
- 村社、物业、养老机构等需要做公共资源台账的组织客户。

### 核心场景

1. 扫码或拍照建立资源库；
2. AI 识别名称、数量、位置和保质期；
3. 用资源图谱查询“在哪、还剩多少、何时到期”；
4. 用数字孪生推演未来 7 天耗尽与浪费风险；
5. 通过 Agent 生成多步处置计划，用户确认后执行；
6. 手机、平板和 2in1 之间同步和接续。

### 核心流程

```text
扫码 / 拍照 / 手动录入
        ↓
字段来源合并与用户确认
        ↓
本地资源图谱 + GraphRAG 证据
        ↓
数字孪生推演未来风险
        ↓
Agent 生成动作计划
        ↓
策略校验 → 用户确认 → 执行 → 结果校验
        ↓
服务卡片 / AI 工作台 / 跨设备接续
```

## 2. 总体架构

```text
┌──────────────────── HarmonyOS 元服务 ────────────────────┐
│ ArkUI 一多界面                                            │
│ AI 工作台 │ 数字孪生沙盘 │ 对话证据 │ 资源库 │ 服务卡片       │
├───────────────────────────────────────────────────────────┤
│ 本地确定性智能层                                           │
│ Resource Twin │ GraphRAG │ Policy Engine │ Groundedness     │
│ Evidence Text │ Barcode Merge │ Reminder Planner            │
├───────────────────────────────────────────────────────────┤
│ HarmonyOS 原生能力                                         │
│ ArkTS / ArkUI │ 元服务 │ Form Kit │ Scan Kit │ 接续         │
│ Preferences │ Camera Picker │ 手机/平板/2in1 断点           │
├───────────────────────────────────────────────────────────┤
│ 云端增强层                                                 │
│ AI 网关 │ LLM │ 视觉识别 │ TTS │ RAG │ 同步 API │ 用量审计   │
└───────────────────────────────────────────────────────────┘
```

### 端云职责

| 层 | 负责内容 | 不负责内容 |
|---|---|---|
| 端侧确定性内核 | 数量、日期、预测、权限、幂等、证据校验 | 不把事实数字交给模型决定 |
| AI 网关 | 模型调用、限流、重试、正文清洗、用量日志 | 不直接决定业务写操作 |
| 用户 | 最终确认写操作 | 不要求用户手工拼装查询 |
| GraphRAG | 给模型提供路径化、来源化的事实证据 | 不生成未存在于图谱的事实 |

## 4. ArkTS / ArkUI 实现

### 状态与重绘

- 主状态使用 `@ObservedV2`、`@Trace`；
- 页面状态使用 `@Local`；
- 复杂对象更新采用“字段更新 + `touch()` 或实例替换”，避免数据变化但 UI 不刷新；
- 数字孪生结果作为纯计算对象重新赋值给 `@Local`，避免页面内重复实现公式。

### 一多适配

`common/Breakpoints.ets` 以设备类型和窗口宽度划分：

- phone：单列、底部 Tabs；
- tablet / 2in1：左侧导航、主内容与右侧 AI 面板；
- wearable：精简入口，仅显示提醒级信息。

数字孪生沙盘在手机上单列，在平板上形成“健康度与风险 + 轨迹与建议”的宽屏布局。

### 原生交互

- `bindSheet`：对话、设置、扫码入库等半模态；
- `Tabs`：功能分区；
- `FormExtensionAbility`：服务卡片数据；
- `UIAbility.onContinue` / `restoreFlow`：任务接续；
- `ScanKit`：扫码输入；
- `CameraPicker` / `PhotoViewPicker`：拍照与相册；
- `Preferences`：用户数据、引导状态、授权和偏好。

## 5. AI 与确定性算法

### GraphRAG

端侧从库、物品、知识库、方案和关系构建个人资源图谱。查询时选择：

- local search：单物品、位置和保质期；
- global search：家庭整体摘要；
- multi-hop：临期食材、菜谱、采购和处置组合。

回答附带路径数与来源行，模型不自行生成数量。

### 数字孪生

按天执行：

```text
qty(t+1) = max(0, qty(t) - dailyUse × familyFactor × mealFactor)
```

输出：

- 首次耗尽日；
- 到期仍剩余数量；
- 健康度分项：新鲜度、充足度、完整度、及时度；
- 行动提示。

来客、减少做饭等情景只改变输入因子，不改变公式，因此结果可对比、可测试。

### Agent 安全

```text
模型工具意图
    ↓
工具白名单
    ↓
角色与数量策略
    ↓
预览确认
    ↓
幂等键
    ↓
业务写入
    ↓
结果刷新与撤销入口
```

模型没有数据库写权限。

### 可解释输出

1. 服务端清除思考过程和内部标签；
2. 端侧对旧消息再次清洗；
3. 数字声明与代码证据比对；
4. 气泡外显示证据来源、路径数量和数字核对状态。

## 6. 难点与解决方案

| 难点 | 解决 |
|---|---|
| 模型偶发输出内部推理 | 服务端裁到正文；空正文直接报错；端侧二次清洗 |
| 模型数字与库存不一致 | 数量由端侧代码计算；回答逐数字对证据 |
| 多件物品扫码归属不清 | 只有一件识别结果时自动绑定条码，多件时拒绝猜测 |
| 元服务通知接口限制 | 实测平台拒绝后改用 Form Kit，不保留不可编译代码 |
| 卡片深链绕过登录 | 目标排队，登录成功后消费 |
| 平板布局挤压 | 显式计算内容宽度与 AI 面板宽度 |
| 图谱与模型职责混淆 | 建图 0 次模型；数值由代码；模型只组织语言 |
| 功能多导致首屏杂乱 | 高级能力收口在 AI 工作台、沙盘和证据抽屉 |
