### 3.5 品牌色与现有主题的关系（决策项）

现有主题主色是品牌橙 `#FF8833`（`Tokens.ets` / `tokens.css`）。新 Logo 是绿-青-蓝系，存在视觉张力。两个方案：

- **方案 A（默认，低风险）**：主题手势不动，Logo 作为独立品牌标识；橙色仍表示"主操作"，青绿用于"AI/生长"语义。
- **方案 B（推荐，视觉统一）**：把主色迁移为 `#0CA8D6`（信号蓝），强调色 `#2FD4B2`，成功色 `#46B14C`；橙色降级为"临期/预算"语义色。需同步五端令牌并重跑对比度校验。

> 落地要求：无论选哪个方案，**令牌只从 `design-tokens.json` 生成**，禁止各端手改色。方案 B 执行前需产品确认（决策项 Q1）。

**验收点**：X1（第 7 章）

### 4.2 M-2 分布式数据对象会话（核心演示点）

**目标**：手机与平板/2in1 之间**实时共享同一份库存会话**——A 设备改数量，B 设备 1 秒内看到变化。

**实现要点**

| 项 | 说明 |
|---|---|
| 会话建立 | `distributedDataObject.create(context, { sessionId: 'nexcore-' + familyId })` |
| 共享数据 | 共享对象只放"轻量快照"：`{ libraries: [{id,name,items:[{name,qty,unit,pos,expDays}]}], updatedAt, by }`（避免超限，图片不入会话） |
| 变更与回写 | `on('change')` 收到远端快照 → 与本地 `store` 做字段级合并（qty 以 `updatedAt` 新者为准）→ 刷新 UI；本地变更 `set()` 推送 |
| 冲突提示 | 同一物品两端 2 秒内都改：以后到者为准 + toast 提示"A 设备已更新数量" |
| 生命周期 | 离开协同页 `off('change')` + `release()`，避免后台常驻耗电 |
| 与云端同步关系 | 分布式会话用于**局域网实时演示**；跨网/异地仍走 `SyncApi`（全量快照 + 409） |

**验收点**：X2、X3

### 4.3 M-3 跨设备拍照入库

**目标**：平板/2in1 上点"拍照"，直接调用**手机**相机拍摄冰箱/衣柜，照片回到当前设备并完成 AI 识别入库。

**实现要点**：`@ohos.multimedia.cameraPicker`（跨设备相机 Picker）→ 选择远端设备相机 → 拿到 `PhotoResult` URI → 压缩（≤1MB，长边 ≤1600）→ 上传网关 `/api/ai/vision` → 识别结果进入既有"补缺确认"流程（复用 `Overlays.ets` 的识别卡片，不新增交互）。

**验收点**：X4

### 4.4 M-4 任务接续（流转）

**目标**：正在填写的"拍照入库确认"或"物品编辑"能迁移到另一台设备继续。

**实现要点**

| 项 | 做法 |
|---|---|
| 序列化 | `Continuation.ets`：把当前流程状态（页面 + 批次 id + 已改字段）序列化为 `want` 参数（≤100KB，剔除图片二进制，只留图片 URI 或缩略图 base64 ≤32KB） |
| 发起 | `UIAbility.onContinue(wantParam)` 写入参数；系统流转入口触发 |
| 恢复 | `onCreate`/`onNewWant` 读到 `continueFlow` 参数 → 直接打开对应浮层并回填 |
| 失败兜底 | 图片仅存本机时：迁移后提示"原图未随行，请重新拍摄"，流程不丢 |

**验收点**：X5

### 4.5 M-5 服务卡片多端适配（运营抓手）

**验收点**：X6

### 4.7 M-7 后端 AI 网关（安全红线）

**目标**：端侧不再持有 Agnes Key；所有模型调用经后端。

| 接口 | 入参 | 出参 |
|---|---|---|
| `POST /api/ai/chat` | `{ intent, evidence, question, profile?, stream? }` | 文本 / SSE 流 |

### 4.8 M-8 知识库 RAG 与来源引用

**目标**：回答"牛奶还能放几天"能给出**知识库来源**（`knowledge/foods.json` 的 `src`）；"今晚做什么"的食材建议命中库存证据。

**实现要点**

1. 打包：`knowledge/*.json` 进 `resources/rawfile/knowledge/`；启动时读入内存索引（失败则回退 `Db.ets` 内嵌子集）。
2. 检索：`KnowledgeIndex.ets` 做两级检索——① 名称/别名精确命中；② 关键词倒排（分词按 2-gram）；命中行带 `src`/`url`。
3. 装配：`Router.evidenceFor()` 把命中行拼成证据块（已有实现，补 `src` 字段）。
4. 展示：`pages/AiPanel.ets` 气泡下方显示来源小字（如"来源：香港食物安全中心"），可点击查看 `sources.md` 对应链接。
5. 红线：**数值仍由代码计算**（保质期天数来自库存 + 知识库默认值），模型只做措辞。

**验收点**：X8
