# 第 1 篇 产品需求

## 1.1 项目概述

**背景**：家庭和个人身边有大量"看得见但记不住"的资源（冰箱食材、衣物、药品、工具、健身器材、书籍等），靠人脑记忆容易遗忘与浪费。本项目通过"拍照 + AI 自动识别分类"，把现实物品低成本数字化成可管理的资源库，并让 AI 基于资源提供规划、预警与建议。

**定位**：一款以"拍照建库 + AI 规划 + 家庭协作"为核心的个人/家庭资源管理助手，覆盖**安卓、鸿蒙、网页、桌面（Qt）、微信小程序**五端（功能对齐），另设 Web 管理员端；数据本地 + 云端混合存储。

**核心价值**：拍照自动建档；资源统一可见；AI 给可执行方案（做什么菜/穿什么）；临期/缺货/重复购买/保修预警；联网增强；自然语言改库存；家庭协作与云端工作台；数据看板；管理员端统一管理。

**典型场景**：冰箱盘点建库 → 晚餐规划（临期优先）→ 勾选核销自动扣减 → 说"鸡蛋只剩 5 个"即改库存 → 全家工作台聚合聚餐规划 → 药品/家电到期提醒 → 看板复盘消耗与浪费。

## 1.4 功能需求明细（F1-F10）

### F1 拍照入库与智能识别
- **F1.1 单张拍照入库**（P0）：拍照/相册选图 → AI 识别名称、类别、数量、品牌规格、建议存放位置、保质期、价格 → 缺失字段补缺 → 一键入库自动归档。
- **F1.2 连拍快速入库**（P1 已确认）：连拍多张 AI 合并去重、数量累加；同一次盘点内合并，不同次不合并。*定稿（D3）：单次 ≤6 张。*
- **F1.3 识别结果补缺与修正**（P0）：任何字段可改后再入库。
- **F1.4 待归类处理**（P0）：无法判类进入"待归类"，用户指定或 AI 后续自动归类。
- **F1.5 价格识别与联网补价**（P1 已确认）：价签可见→"拍照识别"；不可见→联网参考价"联网参考"；均可改，预算以最后确认价为准。
- **F1.6 保质期与存放建议**（P0/P1）：知识库给默认/开封后保质期，用户可覆盖；存放建议（香蕉勿冷藏、土豆洋葱分开放等）。

### F2 资源库管理
- 内置 8 库（冰箱/衣柜/药盒/工具箱/健身器材/书架/宠物食品/家电维修）+ 自定义库；各库典型字段见主文档 3.2 表。
- **F2.1 库管理**（P0）：创建/重命名/删除/排序，内置库可停用。
- **F2.2 物品管理**（P0）：增删改查、图片、手动录入；删除可撤销恢复。
- **F2.3 筛选与搜索**（P0）：按库/类别/标签/位置筛选搜索。
- **F2.4 全局搜索 + AI 问答"XX 放哪了"**（P1 已确认）：跨库全文搜索 + 结合位置字段回答定位。
- **F2.5 私有物品可见性**（P1）：家庭可见/仅自己；仅自己物品不参与共享规划。
- **F2.6 批量导入导出**（P1，Web/Qt 为主）：Excel/CSV、模板下载。
- **F2.7 库存数量手动调整**（P0）：变更进消耗记录与操作日志。

### F3 AI 规划与预警
- **F3.1 食材规划（菜谱方案）**（P0）：基于库存 2-3 个方案，标注优先级/耗时/缺料（可生成采购清单）。
- **F3.2 穿搭 OOTD**（P1）：天气（联网）+场合+季节+衣柜 → 图文搭配。
- **F3.3 健身规划**（P1）：器材库+目标 → 训练方案。
- **F3.4 营养/热量规划**（P1）：减脂/增肌/控糖目标，方案标注热量营养。
- **F3.5 AI 创新菜谱**（P1 已确认）：优先消耗临期食材生成独门菜谱。
- **F3.6 购物清单自动生成**（P1）：方案缺料+低库存合并，一键分享/复制。
- **F3.7 家庭场景规划**（P1）：聚合全家库存做聚餐/出游/家务规划。
- **F3.8 方案优先级规则**（*原待确认*）→ **定稿（D2）**：临期优先 > 清库存 > 营养均衡，固定顺序，不做自定义权重。
- **F3.9 临期/过期预警**（P0）：默认提前 3/7 天两档，可配置。
- **F3.10 低库存预警**（P0）：阈值默认值可配置。*定稿（D4）*：Item 增 `lowAt` 字段（0=不启用），建议值见知识库。
- **F3.11 重复购买提醒**（P1）；**F3.12 药品有效期/用药提醒**（P1）；**F3.13 家电保修期预警**（P1）；**F3.14 宠物食品临期**（P1）；**F3.15 用药打卡**（P1）；**F3.16 使用频次预警**（*定稿（D2）：暂不启用*）。

## 1.5 非功能需求

- **易用性**：拍照 → 确认 → 入库三步内完成；识别结果默认可信，一键全选。
- **响应速度**：识别结果 3 秒内返回（可异步提示）；普通查询 1 秒内。
- **准确性**：常见物品识别准确率目标 ≥90%；数量误差提示人工复核。
- **隐私安全**：照片与库存敏感，默认本地存储，仅协作时上传；聊天不上云；传输/存储加密；共享授权可撤销。
- **离线能力**：本地优先，无网可查改库存，联网自动同步（端侧离线识别模型定稿不做，见 D11）。
- **数据一致性**：版本号 + 操作日志 + 冲突提示。

## 1.6 技术架构

```
客户端（本地优先）: 安卓 │ 鸿蒙 │ 小程序 │ Web │ Qt
        │ 本地数据库 + 同步引擎（全量快照+版本号冲突检测）
        ▼ 上传/下载
统一后端（REST，阿里云 ECS）: 账号与家庭 │ 协作 │ 同步 │ 库存 │ 预警 │ 看板
        ▼
AI 编排网关（Agent）: Agnes(视觉/对话) │ DeepSeek(规划,规划中) │ RAG知识库 │ 联网检索
```

AI 编排示意：用户输入（拍照/文字/勾选）→ 意图识别（入库/查询/规划/修改/预警）→ 工具调用（查库存/识别图片/检索知识库/联网）→ 生成结果 + 结构化动作（扣减/预警/方案/推送/同步）。鸿蒙端已按此落地 M2.5 方案（见第 3 篇）。

# 第 3 篇 AI 开发方案（M2.5，已评审采纳）

依据《通用智能体开发指南_2026版.docx》编制。核心结论：可落地的智能体 = 规则策略管边界 + 检索工具供事实 + 模型处理不确定性 + 状态评测保可控。**不为了 Agent 而 Agent**。

## 3.1 指南落地方针

| 指南原则 | 落地 |
|---|---|
| 事实外置（§1.2） | 库存数量/位置/保质期一律代码查询后作为证据给模型 |
| 自治等级（§2.2） | 查询=A1 只读；改数量/加购物清单=A2 可逆写入，先预览后生效 |
| 分级路由（§4.1） | 高频低价值问题走本地快答，不调模型 |
| 上下文工程（§7.2） | 按意图装配证据（≤30 条、带来源），不全量塞库存 |
| 记忆（§8.2） | 偏好档案仅用户手填（显式确认），AI 不自动回写 |
| 预算（§6.4） | 单请求 ≤2 次模型调用；主模型失败降级备用模型 |

## 3.2 六项功能

| 编号 | 功能 | 文档条目 | 要点 |
|---|---|---|---|
| P0-1 | 意图路由 + 检索式上下文 | F2.4/F5.1/F5.2 | 新增 Router.ets 纯函数模块：greet/where/qty/expiry 快答（0 次模型）；cook/creative/nutrition/summary/兜底走模型；证据带库位/数量/到期/来源 |
| P0-2 | 受约束工具协议 v2 | F5.5/F3.6 | `[调整]` 之外新增 `shopping_add`；白名单执行、名称/数量代码校验、库存无此名直接拒绝（防幻觉写库） |
| P0-3 | 方案营养标注 + AI 创新菜谱 | F3.1/F3.4/F3.5 | 方案卡加「营养速览（约，估算）」；创意菜谱 `[菜]名|耗时|亮点` 解析后逐项回查库存落 Plan，走既有核销/撤销链路 |

| P0-6 | 看板 AI 简报 | F7.7 | 统计由代码算（近 7 天消耗/入库/临期/低库存/最常消耗），模型仅润色，手动触发 |

## 3.3 AI 行为红线（验收安全项）

1. 数量/位置/日期等数值永远由本地查询产出，模型不"报数"。
2. 写操作必须预览确认，可撤销，永不盲写。
3. 单请求 ≤2 次模型调用。
4. 上下文有预算（物品 ≤30 条），偏好可关闭。
5. 模型输出不合规时优雅降级为普通文本，不误伤。
